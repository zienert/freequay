# Contributing

Freequay is a small project run by one person. There is no support and no promised time to answer, but these things help.

## Tell us how a game went

Open a [game report](https://github.com/zienert/freequay/issues/new?template=game-report.yml). A game that runs is as useful to know about as one that does not. Give the Freequay version, your Mac and macOS, and what you tried. Issues are public, and logs can contain your user name and folder names, so remove them first.

A bug in Freequay itself (the app, the `freequay` command, the installation) goes into a [bug report](https://github.com/zienert/freequay/issues/new?template=bug.yml). A security problem is reported in private, see [SECURITY.md](SECURITY.md).

## Write a rule for a game

Settings per game are one line each in the text files in `compat/`; the format is in [compat/README.md](compat/README.md). Try a rule in your own bottle first:

```bash
freequay rule <bottle> steam:<ID> env=<NAME>=<value>
freequay info <bottle> steam:<ID>
```

If it fixes the game, send the same line for `compat/manual.txt` as a pull request, with its fields separated by tabs like the lines there. Put a comment line above it with the game, the date and what you saw, as the existing entries do, and give your Freequay version, Mac and macOS in the pull request. `manual.txt` holds only rules that were tested in Freequay. The other files in `compat/` are generated by `scripts/compat/update.sh`, so do not edit them.

Write rules from your own tests. Do not copy them from AppleGamingWiki, whose license allows no commercial use, or from CrossOver's compatibility database, which is not open.

## Change the code

`app/` is the app (Swift), `scripts/` has the `freequay` launcher and the build scripts, `patches/` holds the changes to Wine, GLib, DXVK and MoltenVK, and `tests/` has small Windows programs that check the pieces. The README explains how to build under "Build". Keep a pull request to one change and say what you ran to test it.

A contribution is under the license of the files it changes. Scripts, the app, tests and documents are MIT; a patch has the license of the code it changes (see "License" in the README).
